# Data

All data in this project is **synthetic**. It was generated by
`scripts/generate_data.py` for a fictional online retailer. It does not describe
real customers, real products, or the performance of any real company, and
nothing derived from it should be read as a real-world finding.

## Generating the files

From the repository root:

```bash
python scripts/generate_data.py            # default seed 42, writes CSVs here
python scripts/generate_data.py --seed 7   # a different, equally reproducible dataset
```

The CSV files are listed in `.gitignore` and are not committed. With the same
seed and Python version, the generator produces identical files (checked on
Python 3.12 by generating twice and comparing checksums).

Expected row counts with seed 42:

| File | Rows |
|---|---|
| customers.csv | 1,000 |
| products.csv | 45 |
| orders.csv | 2,467 |
| order_items.csv | 5,099 |
| payments.csv | 2,598 |
| returns.csv | 307 |

## Generator assumptions

These rules are built into the generator. Any pattern the SQL analysis finds
that matches one of them is a property of the simulation, not a discovery.

- Analysis window: 2024-01-01 to 2025-06-30. All customers sign up inside the
  window, so the customer base starts at zero and grows over time.
- About 8% of customers sign up but never order.
- Three segments (budget, mainstream, premium) differ in order frequency, churn
  and how often they use promo codes.
- Customers order more often from October to December, and promo codes are more
  common in November.
- Promo codes give 10%, 15% or 20% off every line in the order, and slightly
  increase the chance of an extra line.
- About one third of products have a 5% price increase from 2025-01-01, so
  `order_items.unit_price` can differ from `products.list_price`.
- Around 5% of orders are cancelled. Orders in the final week of the window may
  still be `pending` (payment not yet captured).
- Return probability varies by product. Three products are deliberately given
  high return rates. About 10% of returns are rejected with no refund.
- Prices are in GBP and treated as VAT-inclusive. Shipping fees are not modelled.

## Deliberate data-quality issues

A small number of problems are injected on purpose so that
`sql/03_data_quality_checks.sql` has something real to detect. With seed 42 the
generator prints the affected IDs; the counts are:

| Issue | Count |
|---|---|
| Customers with NULL `region` | 6 |
| `completed` orders with no captured payment | 4 |
| `completed` orders with no order lines | 3 |
| Returns where `quantity_returned` exceeds the quantity purchased | 3 |
| Customers whose `signup_date` is after their first order | 5 |
